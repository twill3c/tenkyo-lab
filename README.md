# 典拠ラボ — tenkyo-lab

RAG(検索して答える仕組み)の**検索側を段ごとに開いて測る実験台**。
「RAG を使った何か」ではなく、**RAG そのものを解剖する台**として作った。

本番: (未公開)

## 何を測っているか

法令 26 本を条の項の単位で 13,600 に刻み、条文どうしの内部参照から
**人手ゼロの検索評価セット 2,808 問**を作った。

「第十七条第一項の規定は…準用する」という文から**参照の文字列を消したもの**が問い、
その参照先の条文が正解である。参照は本文に書かれているので、正解は機械的に一意に決まる。

**循環の禁止を三重に置いた。**

1. 問いから参照の文字列そのものを消す(消さないと語の一致だけで当たる)
2. 出題元の条文を検索結果から外す(問いは出題元の本文の一部なので必ず 1 位に来る)
3. 自分の条への参照は捨てる

選別の条件は**問いだけを見て**決めている。「正解と語が重なるか」で選ぶと、
答えを問いに埋め込むことになる。その副作用は別に検算した ——
疎検索が上位 10 に正解を 1 件も入れられない問題が **61.8%** 残っており、偏っていない。

## 分かったこと

| よく言われること | このコーパスでの実測 |
|---|---|
| 意味検索(密)は語の検索(BM25)に勝つ | **ほぼ互角。むしろ BM25 が上**(0.3327 対 0.3374) |
| 両方混ぜれば勝つ | 全体では成立(0.3740)。**ただし法令別では 17 中 2 法令で負ける** |
| 細かく刻むほど良い | **粗いほうが良い**(項単位 0.3327 対 条単位 0.4938) |
| 類似度が高ければ当たっている | **嘘。** 接頭辞を間違えると精度は 16% 落ちるのにスコアは上がる |

Recall@10 の全問平均。

## できていないことも書く

較正の線 16 本のうち **3 本が届いていない**。いずれも計器の側を先に調べたうえで、
**線を下げずにそのまま出している**。

| 線 | 目標 | 実測 |
|---|---|---|
| 密検索の Recall@10 | 0.50 | **0.3327** |
| 疎検索の自己一致 | 1.0 | **0.9960** |
| 量子化の順位保存 | 0.95 | **0.8725** |

## 課金される経路を作らない

- サーバ関数を一つも持たない(`output: "export"` の静的書き出しのみ)
- 埋め込みはビルド前にローカルで計算し、配布物に焼き込む
- 閲覧時の計算はすべて閲覧者の端末で行う。問いはどこへも送られない
- 言語モデルを積んでいない。回答は**条文の抽出**である
- 外部の API を一つも呼ばない(実ブラウザで通信 0 件を確認)

配布の段取りを分けてある。

| いつ | 何を | 量 |
|---|---|---|
| トップページ | **索引を 1 バイトも取らない** | 0 |
| 一問目 | 模型 + 実行系 + 密索引 | 48.48MB |
| つまみ | 疎索引(疎・ハイブリッドを選んだときだけ) | 2.44MB |
| 二問目以降 | 問い合わせの埋め込みと条文の一節だけ | 10.7KB |
| 「測る」ページ | 事前計算した順位のみ(**索引も模型も取らない**) | 0.59MB |

## 画面

| ページ | 中身 |
|---|---|
| はじめに | 何を測っているか |
| 引く | 質問を入れると各段(埋め込み・検索・文脈・回答)の中身がすべて開いて出る |
| 測る | つまみを回すと 2,808 問の指標がその場で動く |
| 効いた・効かなかった | 通説が壊れた場所、届かなかった線、**計器のほうが壊れていた話** |
| 作り方 | 素材の集め方から配り方まで |

## 動かす

```bash
npm ci

# 素材を作る(ネットワークが要る。一度だけ)
npm run fetch          # e-Gov 法令 API から 26 本
npm run chunks         # 条の項へ刻む
npm run oracle         # 参照から評価セットを作る
npm run review         # 目視検分シートを出す

# 索引を焼く(合計 6 時間ほど)
npm run fetch:model && npm run keep-extra && npm run prune && npm run verify:prune
npm run embed && npm run embed:queries && npm run embed:negatives
npm run quantize && npm run pack && npm run vendor && npm run pack:eval

# 測る
npm run eval           # G-01 / G-02 / G-03 / G-08
npm run sweep          # ハイブリッドが負ける条件
npm run prefix         # 接頭辞を間違えるとどうなるか
npm run dump:ts && npm run dump:py && npm run compare   # 二実装照合

# 動かす・検品する
npm run dev
npm run build && npm run inspect   # 実ブラウザ検品(G-11/G-12/G-14/G-15)

npm test && npm run test:py && npm run typecheck
```

## 出典

「e-Gov 法令検索」(デジタル庁)https://laws.e-gov.go.jp/

上記コンテンツを条・項の単位に分割し、検索用の索引を作成する加工を行っている。
加工は本リポジトリの作成者によるものであり、国が作成したものではない。
公共データ利用規約(第 1.0 版)に基づく。

**本サイトは検索技術の実験台であり、掲載する条文は法的助言ではない。**
